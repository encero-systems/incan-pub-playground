Welcome to Incan

Incan is a statically typed programming language for applications, tools, and data workflows. It brings readable source, explicit types, and native compilation together, with access to the Rust ecosystem.

Start learning · Install and get started · Read the documentation

Incan is in beta. 0.6 is in development.

Opening intent: establish the language, let people choose a useful next step, and make its development stage clear. Use the official logo and wordmark in the eventual design. No compiler pipeline or comparison headline here.

A first look at the language

model User:
    name: str
    age: int

def greet_user(user: User) -> str:
    return f"Hello, {user.name}!"

def main() -> None:
    user = User(name="Incan", age=42)
    println(greet_user(user))

A model names the shape of your data. Function signatures make inputs and results explicit. Indentation keeps the structure visible, and named arguments make construction readable.

Your first Incan project

Install the toolchain, create a project, then run, test, and build it.

incan new hello --yes
cd hello
incan oven bake --project .
incan run
incan test
incan build --release

The ideas behind Incan

Readable programs with explicit contracts. Models, function signatures, optional values, results, and mutability help express the shape and behavior of a program in its source.

Native programs, from Incan source. Native compilation is part of the language’s direction. The introductory story belongs to the program you write and run; backend architecture belongs in the technical documentation.

Room for the language to grow. Incan’s longer-term direction includes packages that bring domain vocabulary into checked source. That ambition belongs in the language’s story, with clear links to the roadmap and a distinction between available features and planned work.

Where to begin

Choose a concrete project and see how the language fits the work:

  • A command-line application — organize modules, tests, and a native build.
  • A typed data processor — read structured data, transform it, and handle failures.
  • A web API — work with checked routes and response models.
  • An Incan library — define a public boundary and consume it from another project.
These routes already have documentation. Keep the homepage selective; deeper guides can offer the full range. Each tutorial retains its release compatibility information.
