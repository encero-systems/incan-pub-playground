02 / Descriptions and values

Descriptions define fields. Values supply them.

INCUS / FIELD NOTES

The description names each field and its type. The value supplies the stored data.

A description declares fields with a colon. A value names its type with << and carries its cells in parentheses. The profile description is data; reading it does not execute a model declaration.

03 / References and strings

A reference is different from a string.

INCUS / FIELD NOTES

Without quotes, this path is a reference. With quotes, it is a string.

The slot’s declared type determines which value belongs there. An unquoted declaration path is a reference; its quoted spelling is text. Reading the reference does not follow it or fetch code.

04 / Records and tables

Tables share a description across rows.

INCUS / FIELD NOTES

Each row fills the declared fields in order, including the fields of nested records.

The document supplies the descriptions. A table uses Type << [ … ]; each row fills the declared fields in order. Nested records are rows too. The table is layout: each row remains its own value.

05 / Field identity and renames

Renaming a field preserves its identity.

INCUS / FIELD NOTES

renamed_from records the earlier name so a rename can retain the stored field’s identity.

A stored member’s identity comes from its earliest name. A rename retains that identity. The hash rules distinguish all stored fields, canonical fields and model shape; a matching hash is not proof of who wrote a value.

06 / .COMIC and Crumb

.COMIC can be crumbled.

INCUS / FIELD NOTES

.COMIC is readable text. Crumb is binary. Both represent the same logical typed values.

.COMICTyped valuesCrumb

Readable text

Descriptions, diffs, tests and local files. .COMIC text is never sealed; a cut at an entry boundary can read as a shorter document.

Binary transport

A sealed Crumb set carries a count and a logical-value hash. A reader verifies both before exposing values. A seal detects damage; it does not prove authorship.

The PR stack specifies experimental row and column codecs. Different valid physical encodings can represent the same logical values. That is a format contract, not a universal performance claim.

07 / Historical benchmarks

What the historical benchmarks measured.

INCUS / FIELD NOTES

These counts measure text tokens, not reading accuracy or codec performance.

47,738

.COMIC tokens in an earlier 500-order prototype experiment.

Those historical measurements use the earlier syntax, an inferred schema and an excluded schema cost. They are not benchmarks of the current PR grammar. TOON won two of the eight reported workloads.

No .COMIC language-model reading accuracy was measured. A text-size result also cannot establish binary decoding speed or a production codec.
